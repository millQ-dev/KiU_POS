# 07 — Roadmap, user stories, acceptance и блокеры

**Это proposal порядка работ**, не утверждённые релизные даты и не обещание готовности. Все новые этапы требуют Cursor Origin Level C preflight/ADR, approval владельца продукта по изменениям core state, reviews. Перед стартом сверить реальный Origin/main и уже готовый Operational Core.

## Gate 0 — аудит и архитектура (обязательная)

- Зафиксировать актуальные Origin commits, migrations, APIs, ADR. Привязать accepted PO docs к existing Domain objects (Identity/Order/Payment/Inventory/Procurement/Recipes/Production).
- Согласовать tenant-outlet-warehouse/legalEntity scopes, risk policy grants, separate owner approvals, public @username identity/MFA delta, event audit data retention; no broad «superadmin».
- Дизайн UI карты по пяти кабинетам с linkable objects и one-document design; явно разграничить website Office, KiU Mobile, POS/KDS, guest Q Place.
- Legal feasibility gates: Vietnam taxes/e-invoice/payments/banks, data privacy/photos/selfies, external Accounting Managed qualification, signing/delegated access, mobile platform deeplinks/Wallet.

## Vertical A — shared backbone (dependency)

- GlobalAccount/invitations/scoped grants, outlet selection, role aware hub, owner setup checklist.
- Universal TaskService: four-level priority, manager override reason, context refs, notifications manager-only policy, proof+review toggle, reminders, audit and manual owner escalation.
- Unified primary document service and attachments/phone scan activation, owner approval engine and separate statutory/legal gates.

**AC:** denial tests by grants and tenancy; idempotent duplicate submission; manager-only alert delivery; override reasons; cross-module deep-link.

## Vertical B — Manager launch workspace (priority killer feature)

- Manager live hub linked to shifts/staff/order/table/cash/tasks/issues. Personal shift/selfie checkin, shift swap approved by manager, vacant shift offers, attendance + payroll timesheets.
- Checklist open/close, reservation grants, floor management when table track ready, cash reconciliation, guest incidents, sales goals/Go-list, promo schedule baseline; finance/refund limit approvals.

**AC:** create task without leaving originating context; reviewRequired; reminder; 4 colors, no owner push; schedule swap collision; cash discrepancy immutable; selfie without GPS.

## Vertical C — Chef + Bar shared components

- Chef dashboard/recs; recipes draft + owner publication approval; production batches with off-norm reason, safe inventory grants; purchase route policy; QA checklists, education library, maintenance, optional shift handoff.
- Bar same shared engine; ml stock, kg/ml UOM precision, kegs & loss norms, bar station pools, open-item min-price hard check, zero-price comp with limit, risky event timestamps for future CCTV, manual stop-list, auto low-stock manager suggestion.

**AC:** kitchen and bar don't create duplicate ledger, recipes versioned, out-of-norm without stop except food safety, barcode/unsealed bottles not required as separate stock entities, open item never below price floor.

## Vertical D — Accountant and owner analytical surfaces

- Accounting task home, OCR ingest, shared GR review, AP supplier balances, bank statement import/match, approvals Mobile, e-invoice checks behind provider/legal gates; one independent multi-client review queue for Managed.
- Owner Overview evidence-grade metrics, Sales/Finances/Staff/Warehouse dashboards, AI recommendation cards with sources, settings/grants, multi-location views and onboarding.

**AC:** no fictional providers; owned data export/access retained, cross-client protection, owner finance actions only with grants; AI draft not final.

## Later / gated

- Autonomous draft prep of AI accounting and staffed network after legal/unit economics validation.
- AI production auto-plan as **optional later feature**, not first Chef version.
- CCTV integration, advanced niche/competition data, cross-tenant Q Card/Q Place, wallet loyalty partnerships, nontrivial banking execution only with verified APIs and approvals.

## Minimum QA scenarios to automate

1. Restaurant A staff cannot read/write restaurant B tenant/warehouse; delegated multi-client professional reads only allowed data, write scoped.
2. Owner without expense grant can't create ledger expense; Chef can draft recipe but cannot publish, Manager cannot approve Chef recipe.
3. Manager task priority changed red→yellow lacks reason: reject; with reason: append history and no Owner automatic push.
4. Required manager review flag holds completion, manager approve/reopen works; reminders stop when task truly closed.
5. Employee selfie shift start and swap do not allow overlap/double-booking; unauthorized staff can't swap others.
6. Cash close with discrepancy records count and reason; no fake settlement/fiscal status.
7. Goods receipt transferred across roles remains same document ID; duplicate upload doesn't generate double posted stock.
8. Bar POS open-item lower-than-floor denied server-side irrespective of logged role, discount code or route; comp uses different transaction workflow.
9. Inventory count allowed but posting denied absent distinct grant; stock shared across kitchen/bar and cross-outlet common storage no duplication.
10. Explicit waiter cancel produces KDS HOLD with ACK and manager RESUME/approved cancel, no duplicate tickets; disconnection handled honestly.
11. Overnorm production needs reason yet posts; food safety hard block works; owner notice is separate from manager task channel.
12. Auto low stock never mutates Stop-list; manual chef or bar manager change propagates once to all order channels.

## OPEN product/architecture decisions (don't invent)

- Exact caps, timing and default values for all grants, reminders, notifications, thresholds; manager task re-prioritize relative to SLA and critical safety events.
- Cash shift specific fiscal chronology/guardrails with C0 prepay vs later waiter model; exchange with existing Order/TAX/FISC modules.
- Official banking APIs, bank authentication, Zalo auth vs ADR-0039 MFA, OCR provider/cost, external professional license and legal tax scope, pricing and revenue-share, health/safety retention rules.
- Full Q Place and Q Card separately, not in current five-cabinet delivery.

## Definition of Done for each vertical

- PO story and UI acceptance; API/invariant docs + tests; Permission/server boundaries; migration and reversibility; audit/time zone; observable real provider statuses; no fake production success; cross-channel UX desktop/mobile/POS where applicable; accessibility/localization RU/VI/EN as release target to be set; security/legal signoff as required; Origin PR independent review before merge.
