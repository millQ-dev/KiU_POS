# MillQ Glossary

Shared terminology for product and architecture work. English technical names remain stable in schemas/contracts; the Russian explanation is the owner-facing meaning.

## Business structure

| Term | Plain Russian meaning |
| --- | --- |
| `BusinessGroup` / `Workspace` | Группа бизнеса: контекст, в котором вместе управляют компаниями, брендами и операционными точками; сама по себе не является юрлицом |
| `Organization` | Организация: участник бизнес-отношений, который может выполнять юридическую, управляющую или иную роль |
| `LegalEntity` | Юридическое лицо: официально зарегистрированная компания, от имени которой возникают юридические и финансовые факты |
| `ManagementEntity` | Управляющая структура: организация или, если это будет разрешено, внутренняя структура, которой поручено управлять выбранными объектами |
| `OwnershipInterest` | Связь владения: кто владеет компанией или контролирует её в указанный период |
| `ManagementMandate` | Полномочие на управление: кто управляет рестораном или другой областью бизнеса и в какой период; не является автоматическим доступом в системе |
| `Brand` | Бренд: коммерческое имя/идентичность, под которой ресторан или канал работает для гостя |
| `RestaurantLocation` | Ресторан: конкретная физическая или операционная точка обслуживания |
| `Department` | Подразделение: отдельная операционная часть, например зал, бар, кухня или другая утверждённая зона ответственности |
| `Warehouse` | Складской контур: объект, к которому привязаны операции и область доступа; остатки и движения принадлежат модулю Inventory |
| `Terminal` | Кассовый терминал: стабильная бизнес-точка POS, по которой операции получают контекст ресторана/подразделения |
| `Effective-dated relationship` | Связь с периодом действия: запись, показывающая, когда владение, управление, бренд или другое отношение начало и прекратило действовать |

## Jurisdiction and access

| Term | Plain Russian meaning |
| --- | --- |
| `Jurisdiction` | Юрисдикция: страна или применимая территориальная область правил |
| `JurisdictionProfile` | Версия настроек юрисдикции: набор действующих на период значений по умолчанию и ссылок на утверждённые правила/адаптеры |
| `Default` | Значение по умолчанию: предложенное системой стартовое значение, которое не становится законом само по себе |
| `Override` | Разрешённое переопределение: явная замена значения по умолчанию с сохранением источника и, где нужно, причины/прав |
| `Access scope` | Область доступа: конкретная группа, компания, ресторан, склад или другой объект, внутри которого действует разрешение |
| `Default deny` | Запрет по умолчанию: действие запрещено, пока нет явного подходящего разрешения |
| `User identity` | Учётная личность пользователя: данные для входа и безопасности; не равна автоматически сотруднику или трудовому договору |
| `Employee profile` | Операционный профиль сотрудника: минимальная запись человека/работника для назначения в структуру, смену и аудит; не кадровый и не зарплатный модуль |

## Architecture and data ownership

| Term | Plain Russian meaning |
| --- | --- |
| `Module` | Модуль: самостоятельная часть одной программы со своими обязанностями и данными |
| `Modular monolith` | Модульный монолит: одно развёртываемое приложение, строго разделённое внутри на модули; не набор микросервисов |
| `Domain boundary` | Граница предметной области: правило, определяющее, какая часть системы отвечает за факт и может его менять |
| `Source of truth` | Источник истины: единственный модуль, который окончательно хранит и изменяет определённый класс фактов |
| `Contract` | Контракт: явно описанный способ, по которому один модуль просит другой прочитать или изменить принадлежащие ему данные |
| `Command` | Команда: запрос модулю-владельцу выполнить проверяемое изменение |
| `Query` | Запрос: чтение данных без их изменения |
| `Domain event` | Доменное событие: неизменяемое сообщение/запись о том, что бизнес-факт уже произошёл |
| `Projection` | Проекция: перестраиваемая производная копия данных для быстрого чтения или отчёта; не источник истины |
| `Adapter` | Адаптер: изолированный переводчик между внутренними правилами MillQ и конкретной внешней системой/страной |
| `Provider-neutral` | Независимый от поставщика: внутренний формат, который не содержит специфических типов GrabFood, банка или другого сервиса |
| `Application orchestrator` | Координатор операции: слой, который вызывает несколько модулей по порядку, не забирая себе владение их данными |
| `Immutable` | Неизменяемый: факт не переписывается задним числом; исправление оформляется отдельной контролируемой записью/версией |
| `Snapshot` | Снимок: сохранённое значение, реально применённое к историческому факту, даже если исходный справочник позднее изменился |

## Block B modules

| Module | Plain Russian responsibility |
| --- | --- |
| Identity & Access | Пользователи, минимальные операционные профили сотрудников, назначения, вход, роли, разрешения и области доступа; не кадровый расчёт и не payroll |
| Business Structure | Компании, владение/управление, бренды, рестораны, подразделения, склады и терминалы как структурные объекты |
| Jurisdiction | Страны/регионы, версии настроек по умолчанию и ссылки на утверждённые правила |
| Catalog | Товары, ингредиенты, блюда, модификаторы, единицы и упаковки как канонические справочные данные |
| Recipes & Preparations | Версионные техкарты, заготовки и фактический состав с модификаторами |
| Purchasing | Поставщики, заказы поставщикам и исходные закупочные документы |
| Inventory | Складские движения, остатки, инвентаризации и списания |
| Menu | Представление ассортимента по ресторанам и каналам продаж |
| Pricing & Promotions | Версионные цены, скидки, наценки и правила акций |
| Orders | Заказы и продажи, строки, модификаторы и исторически применённый коммерческий результат |
| Kitchen | Кухонные задания и их отдельное производственное состояние |
| Payments | Оплаты и возвраты как отдельные финансовые транзакции |
| Cash Management | Кассовые смены, денежные ящики, внесения/изъятия и сверка наличности |
| Customer | Профиль гостя, контакты, адреса, заметки и согласия |
| Fulfillment / Delivery | Выдача и доставка заказа, сроки, статусы и будущая работа курьеров |
| Integrations | GrabFood и другие внешние сервисы: подключения, сопоставления и обмен сообщениями |
| Costing | Расчёт и версии себестоимости, включая неопределённость и пересчёт |
| Analytics | Производные отчёты и показатели без изменения исходных фактов |
| Audit & Risk | Неизменяемая история действий и объяснимый контроль подозрительных операций |
| Fiscalization | Будущий отдельный контур официальных чеков/электронных счетов без неутверждённых правил страны |
